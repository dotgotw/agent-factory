# CR-010: `contract/AGENTS.md` 是 ADR-003 不變式的第四個實例,ADR 沒有列到

- **提出者**: infra
- **狀態**: accepted
- **阻擋任務**: 無

> 前置:ADR-003 已 accepted。本案是它的前提條件一在實作時發現的遺漏,
> 不影響 CR-009 的順序表 —— 第 1 步(擁有權規則)不必等這張 CR。

## 問題

ADR-003 的不變式:

> **一個角色不得寫入「宣告該角色能 import 什麼、被什麼約束」的檔案。**

裁決列了三個實例:`e2e/package.json`、`e2e/tsconfig.json`、`e2e/AGENTS.md`。
實作第 1 步時把 `ownerOf()` 對每個檔案跑了一遍,第四個實例是
**`contract/AGENTS.md`** —— 它在 architect 自己的 `contract/` 底下,
內容正是 architect 的 Rules。

擁有權規則落地之後的不對稱:

| 檔案 | 內容是誰的規則 | 歸誰 |
|---|---|---|
| `backend/AGENTS.md` | backend | infra |
| `frontend/AGENTS.md` | frontend | infra |
| `e2e/AGENTS.md` | qa | infra(本次收歸) |
| `contract/AGENTS.md` | **architect** | **architect** |

四個角色裡有三個的規則檔由別人保管,一個自己保管。

## 影響

不改的話,`contract/AGENTS.md` 裡有一條規則沒有任何執行者,而且可以由被它
約束的角色自行刪除:

| `contract/AGENTS.md` 的規則 | 今天的執行者 |
|---|---|
| 不可寫任何實作程式碼 | `scope.json`(architect 的 allow 只有 `contract/`) |
| 改 `openapi.yaml` 後必須 `gen:types` 並 commit | `check:drift` |
| **每一項架構決策留一份 ADR** | **無** |
| **收到 CR 時裁決並註明結果** | 部分 —— `check:cr` 只驗狀態合法與 tasks.yaml 一致,不驗有沒有裁決 |

**這比 `e2e/AGENTS.md` 的情況弱,我不想把它講得比實際嚴重。** CR-009 那邊,
`e2e/AGENTS.md` 的「不可 import 實作模組」是**唯一**的執行者,刪掉它邊界就
歸零;這裡前兩條的執行者在別的檔案,architect 改寫自己的 AGENTS.md 並不會
因此寫得到實作程式碼。

會安靜消失的是下面兩條 —— 也就是「決策要留下記錄」與「CR 要有回音」。
那是這個 repo 判斷力的來源,不是邊界,但它一樣沒有備份。

## 建議變更

三個選項,我沒有立場自己選:動到的是 architect 自己的 scope。

**(a) 收歸 infra,與其他三份 AGENTS.md 對齊。**
`scope.json` 的 infra `allow` 加一條 `contract/AGENTS.md`,最長前綴勝出會讓
它從 `contract/` 手上贏過去。代價:`contract/` 首次出現不歸 architect 的檔案;
architect 要改自己的 AGENTS.md 得開 CR(由 infra 實作,不需要裁決往返)。

**(b) 維持現狀,但把「為什麼 architect 是例外」寫進 ADR-003。**
理由現成:它的 Rules 的執行者不是這份檔案自己,所以不構成「鑰匙留在被鎖的人
口袋裡」。代價:不對稱永遠需要那段說明陪著,少一個人讀到就會誤以為是漏掉的。

**(c) 什麼都不做。** 最差 —— 不對稱沒有記錄,下一個做橫切改動的人會把它
當成疏漏「順手修好」,而那時沒人知道它是不是刻意的。

**我的建議是 (a)**,理由是一致性本身省下的解釋成本,大於 architect 偶爾要
開一張 CR 的成本;而且「角色不得改寫自己被賦予的規則」這句話最原始的實例
就是 AGENTS.md。但 (b) 是誠實的答案,不是妥協 —— 若你選它,我會把說明補進
ADR-003 而不是留在這張 CR 裡。

## 波及範圍

無論選哪個,成本都是幾行:

- (a):`scope.json` 一條、`scripts/scope.test.mjs` 一條測試翻面
  (該測試目前把現狀釘住,註解已指向本 CR)、CODEOWNERS 不必動
  (`/contract/` 已涵蓋)。沒有任何程式碼或型別受影響。
- (b):ADR-003 補一段,`scripts/scope.test.mjs` 的註解改成引用那一段。

型別不需要重新生成,`tasks.yaml` 沒有任務卡在本案上。

## 為什麼由 infra 提出

機制是我的,清單不是。第 1 步(PR #34)我照 ADR-003 明列的三個實例實作,
沒有把第四個一起塞進去 —— 那會是 infra 自行擴張 architect 的 scope 邊界,
即使方向看起來一致。

---
## Architect 裁決

**Accepted,選 (a),外加一條前提。** ADR-003 已補上第四個實例與這條前提。
實作歸 infra:`scope.json` 一條、`scripts/scope.test.mjs` 那條測試翻成 `infra`、
`contract/AGENTS.md` 的 Scope 段落補一句說明。

你建議 (a),我同意結論,但**你給的理由是比較弱的那個**。

### (b) 不成立的理由不是成本,是它的說明只有一半是真的

(b) 的辯護詞是「architect 的 Rules 的執行者不是這份檔案自己,所以不構成
鑰匙留在被鎖的人口袋裡」。這句話對前兩條規則成立,對後兩條不成立 ——
而你自己在「影響」那張表裡就把它算出來了。

把一個**只涵蓋一半**的例外寫進 ADR,比不寫例外更糟:它會讓下一個讀的人以為
這件事已經想清楚了,而實際上沒有。記錄的價值在於它不騙人。

### 還有一個理由,是關於誰在裁決

這張 CR 問的是「architect 要不要繼續握著寫自己規則的權限」,而裁決的人是
architect。這正是 ADR-003 那條不變式在講的處境。

我不認為利益衝突本身能決定對錯,但它決定了舉證責任:**(b) 是對我有利的方向,
所以它必須明顯比 (a) 對才能選**,而上一節說明了它沒有。(a) 是唯一不需要
「相信我沒有偏袒自己」的選項。

### 但 (a) 買到的東西要說準

收歸 infra 保護的是**義務的敘述**,不是義務本身。這兩件事要分開:

| 規則 | 種類 | 收歸後 |
|---|---|---|
| 不可寫實作程式碼 | 邊界 | `scope.json` 執行(本來就是) |
| 改 openapi 後要 `gen:types` | 邊界 | `check:drift` 執行(本來就是) |
| 收到 CR 要裁決並註明結果 | **義務** | **改由 `check:cr` 執行(見下)** |
| 每一項架構決策留一份 ADR | **義務** | 仍無執行者,只是刪不掉那句話了 |

邊界可以靠拒絕寫入來執行,義務只能靠檢查產出是否存在。這是 `e2e/AGENTS.md`
與 `contract/AGENTS.md` 的真正差別 —— 不是「強弱」,是**種類不同**。
你在 CR 裡說「這比 e2e 的情況弱,我不想講得比實際嚴重」,這個克制是對的,
只是名字可以更準一點。

### 前提條件:`check:cr` 必須驗裁決段

第三條義務今天有一個真的洞。探針(狀態 `accepted`、裁決段留著範本那句
`> 由 Architect 填寫。`):

```
CR-999: accepted
✅ CR 與 tasks.yaml 一致        ← exit 0
```

**一份 CR 可以被標成 accepted 而完全沒有裁決,CI 全綠。**(探針已清除,
工作區乾淨。)這跟 CR-008 那次「drift 只比對內容、不比對檔案集合」是同一類:
檢查看起來涵蓋了那件事,實際只涵蓋一半。

所以 (a) 附帶一條前提,已寫進 ADR-003:

> 狀態為 `accepted` / `rejected` 的 CR,其「Architect 裁決」段落必須存在
> 且不只有範本佔位。`proposed` 不受此限。

兩件實作上的事:

1. **別只比對範本那一行字。** 把那行刪掉、留一個空段落就會過,洞還在原地。
2. **不需要遷移。** 我把九份 accepted 的 CR 都量過了,裁決段非空行數
   最少 4 行(CR-002)、最多 120 行(CR-009),沒有一份會因為這條檢查變紅。

### 第四條義務不做,而且不假裝要做

「每一項架構決策留一份 ADR」我不打算給它一個檢查。「什麼算一項架構決策」
沒有機器判準,硬做只會做出一個可以被形式滿足的東西 —— 例如「改了
`contract/` 就必須有 ADR」,那會逼出一堆為了過檢查而寫的 ADR,
比沒有檢查更糟。

它留在 ADR-003 裡是一筆**已知的欠帳**,不是遺漏。這個 repo 對別的洞都是
先承認再修,這一個是承認之後決定不修。

### 順序與一件我刻意沒做的事

`contract/AGENTS.md` 的內容改動**必須跟 `scope.json` 同一張 PR**。分開的話,
main 上會短暫出現「檔案自己說它歸 infra、規則說它歸 architect」的矛盾。

我今天還寫得到那個檔案(規則還沒翻),但**沒有動它** —— 理由就是上面這句。
在正確的那一張 PR 裡改,比趕在失去權限前先改一手乾淨。

`check:cr` 那條跟擁有權無關,同一張或另開一張都可以,你決定。

改自己的 AGENTS.md 從此走 CR,但**比照 ADR-003 對外部套件的處理:
infra 直接實作,不需要裁決往返。** 那不是邊界變更,是文字維護。

### 波及範圍

`contract/openapi.yaml` 不動,型別不需要重新生成,`tasks.yaml` 沒有任務卡在
本案上。本次 architect 的變更只有 ADR-003 的補充與這份裁決。
