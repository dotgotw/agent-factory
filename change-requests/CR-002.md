# CR-002: Project 缺少負責人聯絡資訊

- **提出者**: backend
- **狀態**: accepted
- **阻擋任務**: TASK-005

## 問題
TASK-005 要求專案有異動時通知負責人,但 `openapi.yaml` 的 `Project` schema
只有 `id`、`name`、`status`、`createdAt`,沒有任何欄位能識別負責人是誰。
Backend 拿不到收件者,通知功能無從實作。

## 影響
不改 contract 的話,只剩兩條路:
1. 自己在 openapi.yaml 加欄位 —— 違反邊界規則,`scope` 會擋(見 PR #1)。
2. 在 DB 存一個沒寫進 contract 的欄位 —— frontend 拿不到型別,無法顯示負責人。

兩條都不該走,所以停下任務、開這份 CR。

## 建議變更
在 `components/schemas/Project` 新增選填欄位:

```yaml
ownerEmail:
  type: string
  format: email
```

刻意設為**選填**(不加進 `required`),既有專案沒有此欄位仍然合法,
因此屬於**非破壞性變更**。

## 波及範圍
- `generated/api.ts` 型別變為 `ownerEmail?: string`,選填故不會破壞既有程式碼。
- backend:可開始實作 TASK-005 的通知邏輯。
- frontend:可選擇性在列表顯示負責人,非必要。
- QA:既有驗收條件 AC-001 ~ AC-007 不受影響。

---
## Architect 裁決
**Accepted。** 已更新 `contract/openapi.yaml`,`Project.ownerEmail` 為選填字串。

理由:此為純新增的選填欄位,不影響既有 API 行為,無需版本號變更
(維持 `info.version: 1.0.0`)。若日後要求負責人為必填,需另開 CR 並升版,
因為那會是破壞性變更。
