# CR-015: 一個任務一條 session —— context 是稅率,不是餘額

- **提出者**: architect
- **狀態**: accepted
- **阻擋任務**: 無

> 不阻擋任何任務。但它解釋了一件今天已經發生的事:5 小時額度重置的那一刻,
> 額度就是滿的 —— 沒有人做任何事,連發問都不行。
>
> 這不是省 token 的技巧問題。是**預設值錯了**:繼續留在同一條 session 是阻力
> 最小的路,而它同時是最貴的路。沒有任何機制會在任務邊界上叫住你。

## 問題

### 量到的東西

2026-09-03,兩條角色 session 的狀態,以及「醒來說一句話」的成本:

| session | context | 冷回一次的成本 | 佔 Pro 5 小時額度 |
|---|---|---|---|
| Infra Agent | 840.9k | 約 $5.3 | **~26%** |
| Architect Agent | 687.4k | 約 $4.3 | **~21%**(實測) |
| 當天新開的 session | 109.8k | 約 $0.7 | ~4%(實測) |

機制是 prompt cache。穩定前綴(系統提示詞、工具定義、`CLAUDE.md`/`AGENTS.md`、
對話歷史)命中快取時只付原價的 ~0.1x,但**快取 TTL 是 1 小時** —— 閒置超過一小時,
整份 context 必須以 1.25x 重寫。

那個係數是用實測反推的:687k 的 session 冷回實際掉 21%,反推 Pro 的 5 小時額度
約值 $20。拿它去預測 109.8k 應該掉 3.4%,實際看到 4%。對得上。
(額度換算權重不公開,所以這是**量出來的係數,不是官方數字** —— 當數量級用,別當帳單。)

**注意兩個鐘不同步。** 快取 TTL 是 1 小時,額度窗口是 5 小時。快取通常在重置之前就早死,
所以「等額度重置再回來用那條大 session」買不回快取 —— 重置後第一次動它,一樣是全額重寫。

### 形狀:context 是稅率,不是餘額

直覺會把 context window 當成一個**額度**:1M 是上限,用到 840k 表示「還剩 16%」。
那個直覺是錯的,而且錯得很貴。

實際上每一輪都按**當下的 context 大小**抽一次成:

| | 每 100k context 的單輪成本 |
|---|---|
| 熱(1 小時內) | ~0.25% 的 5 小時額度 |
| 冷(隔超過 1 小時) | ~3% |

所以真正的問題從來不是「我到頂了沒」,是:

> **我還在為多少已經用不到的東西付稅?**

一條 session 連做五個任務,做到第五個的時候,前四個任務的 context 全是死重 ——
但每一輪照抽。840k 裡真正在用的可能只有一成,其餘九成是每講一句話就要付一次的房租。

**觸發點因此不是某個數字,是任務邊界。** 任務一結束,那一整段 context 瞬間從資產
變成純稅。那一刻關掉它是免費的,帶著它走則要付到 session 結束為止。

### 更正:第一版的判準是壞的,而且壞在最關鍵的地方

這份 CR 的第一版主張的判準是:**「當某條 session 開始『不敢關』,就是該寫進 repo 的信號。」**
它假設的因果是「狀態卡在 session 裡 → 所以不敢關」。

實際問過當事人之後,那不是發生的事。真正的原因是**懶得開新的** —— 就讓同一個角色
一個任務一個任務做下去,沒想過會這樣計費。

這兩者差很多,而且致命:

> **一個懶得開新 session 的人,永遠不會感覺到「不敢關」—— 他根本沒問過那個問題。**

也就是說,那條判準**在它最該生效的案例上失效**;840k 那條正是被它漏掉的。
這跟 CR-014 記的是同一個家族:

> **依賴自覺的判準,在最需要它的時候失效。**

CR-014 的版本是「拿當下的狀態當前提」,這裡的版本是「拿當事人會注意到當前提」。
所以主規則必須是**不需要自覺的機械預設**,而「不敢關」只能當例外處理。

## 影響

不改的話會被迫做出的妥協有三個,三個都已經發生過:

**一、額度被存量吃掉,不是被工作吃掉。** 今天重置的瞬間就是 100%,原因是兩條大 session
還在那裡等著被喚醒。做事的預算跟養 session 的成本搶同一個池子,而後者不產出任何東西。

**二、「再試一次」變成最貴的動作。** 大 session 撞到上限後,最自然的反應是等重置、
按 Try again —— 那剛好是全額重寫,錢付完了還沒拿到一個字。實測就是那 21%。

**三、「不用壓縮」這個建議,少了半句就會反過來咬人。** 當事人先前問過要不要適時壓縮,
得到的答案是不用。那句話單獨看不算錯,但它漏了一個區別:

| | 代價 | 適用時機 |
|---|---|---|
| 壓縮 | 付一次全額掃描 + 損失細節 | 任務**做到一半**、context 已大、還不能收尾 |
| 關掉 | **免費** | 任務**邊界上** |

在任務邊界上,關掉嚴格優於壓縮 —— 你本來就不需要上一個任務的細節。
「不用壓縮」如果配上「但做完這個任務就關掉」,不會有今天這個結果。

## 建議變更

### 主規則(機械,不需要自覺)

> **一個任務一條 session。任務換了就換 session。**

這條之所以是主規則,是因為它不要求任何人注意到任何事。而且邊界現成就有 ——
`tasks.yaml` 的 `TASK-NNN` 已經是第一類概念,`pnpm task TASK-042` 查的就是它。

**這跟 worktree 無關。** worktree 是一個角色一個目錄,不必動;換的是 session,
同一個 worktree 底下開新的就好。

### 例外處理(這裡才輪到「不敢關」)

> **到了任務邊界卻關不掉 —— 那是狀態還沒落地的信號,不是繼續用下去的理由。**

關不掉代表那條 session 的 context 是某份狀態的唯一副本。這時候依 ADR-009 把它安置好:
決策進 `contract/decisions/`,跨 scope 的進 `change-requests/`,下一個人會再踩的留坑註解。
寫完就關得掉了。

### 落地位置(三處,全部在 infra 的 scope)

**一、`AGENTS.md` —— 在「發現坑怎麼辦」之後加一節。** 建議文字:

```markdown
## session 是拋棄式的

**一個任務一條 session。** 換任務就換 session —— 不是因為 context 會滿,
是因為 context 是稅率不是餘額:每一輪都按當下的大小抽成,而上一個任務留下的
那一段,從任務結束的那一刻起就只剩稅,沒有用途。

粗略的價目:**每 100k context,熱的時候每輪約抽 0.25% 的 5 小時額度;
隔超過一小時再回來,那一次是 3%**(快取 TTL 是 1 小時,過期整份要以 1.25x 重寫)。
一條 800k 的 session 光是醒來說一句話就是四分之一的額度。

到了任務邊界卻**關不掉**,那是狀態還沒落地的信號 —— 決策進 `contract/decisions/`,
跨 scope 的進 `change-requests/`,下一個人會再踩的留坑註解。寫完就關得掉了,
而關掉是免費的。

(做到一半、還不能收尾但 context 已經很大 —— 那才是壓縮的場合。
在任務邊界上,關掉嚴格優於壓縮。)
```

這一節落在手寫區,不在 `<!-- AGENT-FACTORY:START -->` / `END` 之間,
`pnpm sync:agents` 不會覆蓋它。

**二、`.claude/` 的 agent-workflow skill §6。** infra 剛把「交辦訊息要帶足夠的狀態」
寫進 §6(#112)。這條是同一段的自然下一句:交辦訊息要帶狀態,是因為收訊息的人不能靠
你的 session;而**你自己明天也不能靠它**。兩句放一起,讀的人不用自己拼。

**三、`scripts/role.mjs` 的開場提醒。** 這一處最值錢,因為 `pnpm role` 是唯一會在
**session 開場**被看到的地方 —— 而主規則正好是開場才管用的:「這條 session 要做哪個
任務?做完就關。」它不需要偵測 context 大小,只需要在開場把預設值講一次。

(第一版我把這一處寫成「要偵測 context 長大」,那是配合舊判準的設計。改成機械預設之後
反而簡單了:開場講一次就好。)

## 波及範圍

- **infra** —— `AGENTS.md`、`.claude/`(skill §6)、`scripts/role.mjs`。三處都是 infra
  的路徑,一份程式邏輯都不用改,沒有型別重新生成,沒有編譯失敗。
- **architect(我)** —— 若接受,我把「依賴自覺的判準在最需要它的時候失效」這條形狀
  併進 `contract/decisions/ADR-009-where-knowledge-lives.md`。那是我的 scope,不必等
  這份 CR;但**落地的三處都不是我的**,所以先開 CR。
- **所有角色** —— 沒有程式要改,但預設值要改:一個任務一條 session。

## 為什麼是 CR 而不是傳訊息

`AGENTS.md`、`.claude/`、`scripts/` 都不是 architect 能寫的 —— 依 ADR-003,
角色不得寫入宣告自己邊界的檔案。這是被擋下來的標準出口。

還有一個更直接的理由:**這份內容如果用訊息發,就會示範它自己在反對的東西** ——
一則主張「session 裡的東西不算數」的訊息,收訊息的那條 session 一壓縮它就沒了。

附帶一提,這份 CR 是 proposed,所以依 CR-014 記的那個 bug,它會讓 `pnpm verify`
紅在 `check-cr.test.mjs:127`。**我在 architect 分支上撞到的,跟 qa 在
`qa/record-cancelled-intermittent` 上用 CR-013 撞到的是同一條** —— 兩條互不相干的
分支、同一個機制、同一個位置。這是 CR-014 的獨立佐證,它「改用合成 fixture、不要依賴
repo 當下狀態」那條建議因此更站得住。這份 CR 要等那裡修好才送得出去。

裁決歸屬:三處變更全在 infra 的 scope,實質決定權在 infra,不在我。下面的裁決段留空
是格式要求(`check-cr.mjs` 要求 proposed 的 CR 裁決段必須是空的)。

---
## Architect 裁決

**accepted。實作由 #119(`7ec2ea6`)落地,早於本裁決。** 沒有 contract 變更。

實質決定權在 infra(提案人是我,變更全在他們的 scope),他們同意並照 CR-017 的先例
先做後裁。三處都驗過:

| 落地點 | 現況 |
|---|---|
| `AGENTS.md`「session 是拋棄式的」 | 本 CR 的建議文字原樣落地,在手寫區,`sync:agents` 不會覆蓋 |
| skill §6 | 接在 #112「交辦訊息要帶足夠的狀態」後面,**指回 `AGENTS.md` 拿價目表而不是複製一份** |
| `scripts/role.mjs` | 開場實測到:`這條 session 要做哪個任務?做完就關 —— 換任務換 session(見 AGENTS.md)。` |

skill 那處指回去而不是複製,值得記一筆:價目(0.25% / 3% 每 100k)只有一份正本,
兩邊都寫的話下次調整就會漂移,而這個 repo 沒有檢查在守那種漂移。

### 這條規則的第一個案例就是產生它的那條 session

本 CR 的資料來自兩條養到 840k / 687k 的角色 session,而**寫出這份 CR 的 session
自己也在同一條路上** —— 它從「為什麼用量掉這麼快」一路做到裁決五份 CR、派兩棒實作,
沒有在任何任務邊界關過。

這不算反諷,算佐證:主規則之所以要是機械預設,正因為**當事人在過程中不會感覺到不對**。
第一版判準「不敢關」失效的理由(懶得開新的人永遠不會問那個問題)在這條 session 上
又應驗一次 —— 我提出它、寫下它、然後繼續沒有照做。

### 欠帳:機械預設仍然只是一句話

`pnpm role` 開場那行是提醒,不是強制。沒有任何東西擋得住一條 session 做完任務繼續往下做,
而依 ADR-009:77 的先例,這種欠帳要明說而不是假裝有機制。

不建議去做強制。能想到的做法(依 context 大小拒絕服務、依任務邊界自動歸檔)都會在
「做到一半但還不能收尾」那格誤傷,而那一格正是本 CR 說要用壓縮處理的情況。
**提醒放在開場、判準寫在 `AGENTS.md`,已經是這個機制能到的位置。**
